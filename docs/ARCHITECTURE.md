# NEXUS ANALYTICS v2 — единая архитектура

Один репозиторий, одна база данных, один интеграционный шлюз, одно тестовое развёртывание. Не плодить репозитории и не смешивать тестовую информацию с реальными данными.

## Слои

- **Приложение:** React / Vite / TypeScript, iPhone-first. Продакшен v1.0 остаётся доступным без изменений; v2 разрабатывается отдельно.
- **Данные:** Supabase `mjqicmrwstqypwnvtkyf`, нормализованные таблицы `na2_*`, связность по UUID + user_id, RLS ограничивает каждого пользователя его собственными записями.
- **Интеграции:** Edge Function `nexus-company-research`, Банк России и ограниченный поиск; официальный доступ к ЕИС/ФНС/КАД не заявляется до появления проверенного API и законного разрешения.
- **Статус записи:** `unverified`, `source_linked`, `user_verified`, `official_verified`. Ссылка без чтения документа не является подтверждением. Судебный иск не является доказательством долга или правонарушения.
- **Демо:** полностью синтетические компании и ценовые предложения без реальных ИНН, не сохраняются в БД. Ни один демо-результат не прибавляется к реальным суммам.
- **Развёртывание:** отдельный Vercel staging из ветки `nexus-analytics-v2-staging`. Основной v1.0 Vercel проект не изменять до прохождения acceptance.

## Единый контракт данных

Компании → продукция → рыночные предложения; компании → участие/победа/договор; компании → судебные дела; компании ↔ отношения. Наличие товаров фиксируется отдельно от цены. Все сущности имеют собственный источник и статус проверки.

## Acceptance gate

1. Приложение разворачивается по конкретному commit, TypeScript проходит, unit tests проходят.
2. Публичный DEMO открывается на iPhone и честно маркирован.
3. После регистрации A создаёт компанию, товар, предложение, участие, договор, судебную запись; данные сохраняются после обновления.
4. B не видит и не может редактировать данные A — проверить раздельными JWT с RLS, не только UI.
5. Поиск ИНН проверяет живые реквизиты Банка России без вымышленных судебных/тендерных результатов.
6. Отсутствие источника ясно отмечено; ошибка сети не превращается в фиктивные данные.

## После gate

Подключать официальный экспорт ФНС/ЕИС и КАД только через нормализованный адаптер с журналом загрузки, ограничением квот, идемпотентностью и исходным документом. Добавить версии схемы, API и полноценный мобильный E2E с реальными аккаунтами. Не запускать платные API без отдельного согласия.
